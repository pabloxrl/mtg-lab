## Independent expectations and test-first evidence

[Initial compiled behavioral red](initial-red.log) ran the executable with schema
2 configuration before implementation: one-choice and work/record-limit tests
failed because native configuration was rejected. Negative validation passed.
[Follow-up compiled benchmark red](bench-red.log) caught shared validation allowing
native configuration to run through the passive benchmark; explicit schema-1-only
benchmark validation repairs it without changing legacy benchmark behavior.

Normal-discovery `crates/mtg-cli/tests/native_simulate.rs` covers:

- Real closed-stdin/no-display native games: both starting seats; homogeneous
  LegalRandom, homogeneous Heuristic and mixed policies; environment/policy seed
  42, episode 7. Repeat all JSONL and compare accepted semantic history digest,
  life/turn/active seat/step/public zones, hand/library counts, terminal predicates and decisions
  to independent orchestration of the delivered Game and policy libraries.
  Actual actions must include land and spell selections in every workload;
  homogeneous heuristic also requires nonempty attackers.
  Equality is not the rules oracle: CR704.5a/b public loss predicates and winner
  accounting are checked separately; no winner generated by this CLI is frozen
  as an expected winner.
- Literal both-seat first-land checkpoint from explicitly ordered normal-reset
  green decks: two keeps + two upkeep passes + one Forest play = five decisions.
  CR103/103.8a/117/305 independently require turn 1, life 20/20, hands 6/7 by
  starter, libraries 33/33, one untapped Forest and empty remaining public zones.
  This is actual native-policy play, not a synthetic sibling engine or script.
- One opening decision cannot be a rules outcome. Exact quantum-one/reset-only
  work cap leaves zero decisions and unavailable views. One history slot permits
  one decision then fails the next, preserving requested/started/not-started.
- Missing/malformed versions/policies/bounds, episode-ID overflow, stdout failure,
  and refusal to silently run native config as passive bench.
- Bounded real SIGTERM and SIGINT smoke waits for a flushed header, then checks
  only exit/accounting invariants; no wall-time-based expected decision counts.

Unit tests in `native.rs` inject deterministic stop/deadline controls before start,
after exactly one accepted choice and after 199 total work calls (including reset).
The later stop asserts more than two decisions, not an exact decision count. Pre-start has
zero started; active signals are incomplete, deadlines truncated, with two of
three episodes not started. Maximum-u64 episode count stops before any allocation.
Explicit synthetic unavailable-policy and write/flush failures supplement real
played acceptance; caller errors cannot become rules failures, wins or draws.
Existing pass-v1, benchmark, replay, conformance and trajectory tests are retained.

The first-land test initially mislabeled the Forest `summoning_sick: true`.
[Retained failed assertion](checkpoint-correction-red.log) and [separate independent
review](expectation-review.json) preserve this authoring error. The reviewer
approved false using CR302.6, the documented creature-only view contract, prior
casting evidence and the existing positive creature-sickness assertion. All other
literal checks remain, with a rationale beside the corrected assertion. This was
not an implementation-output oracle; the focused review is not candidate approval.

A later full-suite run caught an overstrict new assertion requiring every random
or mixed game to attack. The failing seed/workload and all direct/repeat/state
assertions are retained. [Independent policy-contract review](attack-expectation-review.json)
approved keeping the attack assertion for homogeneous heuristic: legal-random
explicitly permits pass/cancel/empty attacks, whereas heuristic attacks with
legal attackers. [Failed full-suite log](attack-correction-red.log) is retained.
The review also requested stronger empty-draw predicates: the losing seat must
be active in the draw step as well as have zero library cards. Those assertions
were added; no observed winner or action trace became an expected constant.

include the executable native fixture. The driver alone owns rules/history and
finalization; capture is disabled. Work-call exhaustion is honestly incomplete,
not a rules terminal or value-bootstrap truncation. Limits are not byte/RSS bounds.

reference agreement, performance or playing-strength qualification is claimed.
