# Shared cleanup and discard continuations (GH-139)

Four original scripts extend the shared native/XMage test executor through cleanup
and the next turn's upkeep. They cross seven/eight cards at cleanup with two/four
marked damage on a Growth-boosted Bear Cub. No production rules change.
This is bounded, partial R0002-B017/B026/B029 evidence; #115/#18 integration, M1
qualification, Forge, full-pool, dual-reference and full-game gates remain open.

## Independent specification and exact setup

The [input](../../../fixtures/reference/instant-responses.json) cases `cleanup-7-2`,
`cleanup-7-4`, `cleanup-8-2` and `cleanup-8-4`, and their
[literal expected checkpoints](../../../fixtures/reference/instant-expectations.json),
were authored before adapter implementation from the pinned
[CR 2026-09-25](../../../data/rules/cr-2026-09-25.json) and
[Oracle manifest](../../../data/cards/foundations_micro_v1.json).
They were not generated by either engine, nor borrowed from upstream tests.
The existing independently specified destination-response prefix is reused.

Both engines start at turn-one P0 upkeep priority with 20 life each, zero mana,
empty libraries and all objects listed in insertion order. Each player controls
an untapped, undamaged Bear Cub since before the turn. P0 has Forest/Mountain,
Bite Down and seven/eight named filler lands; P1 has Forest and Giant Growth.
The four-damage cases additionally give P0 another Forest/Mountain and Bite Down.
Hands are installed at the declared upkeep boundary, bypassing opening/mulligans.
No draw or shuffle occurs: P0 skips its first draw (CR 103.8a), and the script ends
at P0's response window in P1's next upkeep, before its draw step. The native
synthetic RNG is `splitmix64-v1`, seed/episode zero, with no random result used.

P0 casts Bite, P1 responds with Growth on its own Cub, and both spells resolve
through explicit target/payment/pass choices. Oracle gives the Cub 2/2 and
Growth +3/+3 until end of turn; the Cub survives two damage as 5/5. In the
four-damage variant a second real Bite deals another two, for four marked damage.
Explicit passes and an empty attacker declaration reach the end step. No combat
choice is invented or selected by AI.

CR 514.1 requires P0 to discard exactly one card only in the eight-card cases.
The script selects the interior hand card `keep3` (a Forest); same-name Forests
remain, so matching a name/count cannot establish the requested identity.
The discard checkpoint must still show a 5/5 with two/four damage. It observes
an actual discard choice, **not priority**. CR 514.2 removes marked damage and
ends Growth simultaneously; CR 704.5g must not destroy a transient 2/2 with
lethal damage. Both Cubs remain on the battlefield. CR 514.3 grants no priority
in this cleanup. CR 500/502/503 proceed to P1's turn and untap its Forest before
upkeep priority, followed by an explicit pass to P0. The next Cub state is 2/2,
zero damage; the seven-card hand is unchanged or excludes exactly `keep3`.

## Observation and strictness

Every prior checkpoint assertion remains, with stronger ordered hand/graveyard
observations on all eleven shared cases. Hand order is the declared insertion
order contract (not a claim that Magic forbids rearranging one's hand).
Graveyards are oldest-to-newest; spells precede the cleanup discard. The stack
remains bottom-to-top with historical target incarnations. Named objects retain
actual current zones/incarnations, owner/card checks, taps, creature stats/damage,
life, mana, damage events, resolution results and combat membership. Empty
libraries/exile and complete inventory are still enforced.

The native adapter reads its actual `Discard` decision and maps exact card IDs
to legal candidate indices. XMage's actual `TargetDiscard` callback supplies the
required cardinality; the bridge rejects wrong actors, counts, duplicate IDs or
cards outside that hand, then supplies those exact IDs. XMage keeps a stale
priority-player field during cleanup; the discard callback is exported with
`priority: null`, and the bridge rejects any actual cleanup priority callback.
No successful state is manufactured from expected results or passed to an engine.

Normal discovery contains the full literal executions, omissions/duplications of
every cleanup script item, strict discard identity/count/actor checks, and Python
comparator controls for early expiration/removal, retained boost/damage, death,
hand/graveyard order, exact discard identity, extra discard, invented priority
and wrong next active player. Existing unavailable-reference rejection remains.
[red.log](red.log) preserves the compiling baseline failure at an unsupported
cleanup-continuation checkpoint.

The separate reference runner repeats all eleven shared cases twice per engine,
then executes bad discard controls in each: missing/extra/empty/two-card/foreign/
wrong-actor discards, an invented cleanup pass, and a discard on the seven-card
path. A different legal Forest discard executes but must diverge at the next
upkeep's exact identity. Reduced one-case input, observations, logs and the first
divergence are retained. Observation fault injections are explicitly comparator
controls, not claims that an engine executed the injected bad state.

Separately, [compiled controls](compiled-controls.json) perturb the native rules
executor immediately before publishing the cleanup discard decision. One clears
marked damage early; the other expires the boost early, exposing an invalid intermediate 2/2
with four damage at the discard choice. This mutant does not itself run lethal
state-based actions or claim an observed death. Both real executions first diverge at `before-discard`.
The exact patches, mutant observations and logs are retained. The production
source was restored byte-for-byte before final acceptance and full torture;
no mutant or production rule change belongs to this delivery.

[Final acceptance](acceptance.json) records agreement for all eleven cases twice
per engine, nine new live cleanup controls and twenty cleanup observation faults,
alongside all existing instant/departure/blocker controls. [Full torture](torture.json)
passed 143 Python tests and 280 Rust tests plus two doctests in each debug/release
profile, with docs/program/catalog/fmt/Clippy checks. [Specification checks](specification.json)
verify the official CR checksum and preservation of all seven prior case expectations.

## Reproduction and provenance

Run inside the managed Linux ARM64 Docker worker; no Docker invocation or socket
is needed. Reuse the prepared external cache, or copy the image cache once:

```sh
cp -a /home/agent/.cache/xmage /tmp/mtg-xmage
python3 scripts/instant_reference.py --cache /tmp/mtg-xmage --output /tmp/cleanup-acceptance
cargo test -p mtg-core --locked --lib instant_
python3 -m unittest discover -s tests -p test_instant_reference.py
./scripts/torture.sh
```

Every file listed in the acceptance receipt’s artifact inventory is retained in
this directory, including the legacy controls’ logs. The initial independent
review’s advisory about missing logs is resolved by retaining the complete inventory.

The acceptance receipt pins scenario/expectation/bridge/native-source hashes,
source/archive and card/rules revisions, Java/Maven/dependencies and Rust/Python
versions. Reference execution is offline, headless, stdin closed and bounded.
An unavailable/failed reference removes a stale success receipt and retains a
failure artifact; it never passes. New consulted cleanup/selection/ordered-card
APIs are pinned in [XMage pins](../../../references/xmage/pins.json); the
[upstream MIT notice](../../../references/xmage/UPSTREAM-LICENSE.txt) is retained.
Scenario, expectations and bridge additions are original project material.
No Forge code or new rules/card text is redistributed; release-license questions
remain with their existing owners.

Limits: synthetic setup is not normal reset/reachability evidence. No legal-action
enumeration, player-private view validation, cleanup triggers/additional cleanup,
next-turn draw, general combat or full-game verification is claimed. Library
order is unexercised because libraries stay empty. Exact hand/graveyard order is
observed, not merely inferred from object membership. Full torture, separate
candidate review, protected merge and exact-main CI are recorded in the
[issue workpad](https://github.com/pabloxrl/mtg-lab/issues/139).
